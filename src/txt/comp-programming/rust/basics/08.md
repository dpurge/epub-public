# 08

## Cel rozdziału

Rozdział 8 omawia trzy najczęściej używane kolekcje ze standard library:

- `Vec<T>`
- `String`
- `HashMap<K, V>`

Wszystkie przechowują dane na heapie, więc mogą rosnąć lub maleć w runtime. Różnią się jednak modelem dostępu, kosztami i typowymi zastosowaniami.

## `Vec<T>`

Vector przechowuje wiele wartości tego samego typu obok siebie w pamięci.

### Tworzenie

Pusty vector:

```rust
let v: Vec<i32> = Vec::new();
```

Z wartościami początkowymi:

```rust
let v = vec![1, 2, 3];
```

Jeśli przekazujesz wartości, Rust zwykle sam wywnioskuje typ elementów.

### Dodawanie elementów

```rust
let mut v = Vec::new();

v.push(5);
v.push(6);
v.push(7);
```

Ponieważ `push` zmienia zawartość, vector musi być mutowalny.

### Odczyt elementów

Są dwa podstawowe podejścia:

```rust
let v = vec![1, 2, 3, 4, 5];

let third: &i32 = &v[2];
let third: Option<&i32> = v.get(2);
```

Różnica semantyczna:

| Sposób | Poza zakresem |
|---|---|
| `v[index]` | panic |
| `v.get(index)` | `None` |

Czyli:

- `[]` używaj wtedy, gdy brak elementu ma być błędem programu,
- `get` wtedy, gdy sytuacja może być normalna i chcesz ją obsłużyć.

### Borrow checker a realokacja

Nie wolno trzymać referencji do elementu vectora i jednocześnie wykonać operacji, która może zmienić cały vector, np. `push`, jeśli później ta referencja nadal jest używana. Powód: vector może się przealokować i przenieść dane w nowe miejsce pamięci.

## Iteracja po vectorze

Niemutowalnie:

```rust
let v = vec![100, 32, 57];

for i in &v {
    println!("{i}");
}
```

Mutowalnie:

```rust
let mut v = vec![100, 32, 57];

for i in &mut v {
    *i += 50;
}
```

Przy mutowalnej iteracji trzeba użyć `*`, bo `i` jest referencją mutowalną do elementu.

### Wiele typów w jednym vectorze

Sam `Vec<T>` jest jednorodny, ale można obejść to przez enum:

```rust
enum SpreadsheetCell {
    Int(i32),
    Float(f64),
    Text(String),
}

let row = vec![
    SpreadsheetCell::Int(3),
    SpreadsheetCell::Text(String::from("blue")),
    SpreadsheetCell::Float(10.12),
];
```

To działa, bo wszystkie elementy są jednego typu: `SpreadsheetCell`.

### Drop

Gdy vector wychodzi ze scope, dropowane są również wszystkie jego elementy.

## `String`

`String` to mutowalny, owned, growable tekst UTF-8. Nie jest wbudowany w core language; pochodzi ze standard library.

Ważne rozróżnienie:

- `String` — owned, mutowalny tekst,
- `&str` — borrowed string slice.

## Tworzenie `String`

```rust
let mut s = String::new();
```

Z literału:

```rust
let s = "initial contents".to_string();
let s = String::from("initial contents");
```

Obie formy są równoważne praktycznie; wybór to kwestia stylu.

### UTF-8

`String` i `&str` są UTF-8, więc mogą przechowywać tekst w wielu językach bez osobnych typów.

## Modyfikacja `String`

### `push_str`

```rust
let mut s = String::from("foo");
s.push_str("bar");
```

`push_str` bierze `&str`, więc nie przejmuje ownership doklejanej wartości.

### `push`

```rust
let mut s = String::from("lo");
s.push('l');
```

`push` dodaje pojedynczy `char`.

## Konkatenacja

### `+`

```rust
let s1 = String::from("Hello, ");
let s2 = String::from("world!");
let s3 = s1 + &s2;
```

Kluczowe skutki:

- `s1` zostaje przeniesione,
- `s2` jest pożyczane jako `&str`,
- wynik to nowy `String`.

Powód wynika z podpisu logicznie odpowiadającego:

```rust
fn add(self, s: &str) -> String
```

Czyli:

- lewy operand jest konsumowany,
- prawy operand jest pożyczany.

### `format!`

Przy większej liczbie stringów zwykle lepsze:

```rust
let s1 = String::from("tic");
let s2 = String::from("tac");
let s3 = String::from("toe");

let s = format!("{s1}-{s2}-{s3}");
```

`format!` jest czytelniejsze i nie przejmuje ownership argumentów.

## Dlaczego `String` nie wspiera indeksowania

To jeden z ważniejszych punktów rozdziału: `String` nie pozwala na `s[0]`.

Powody:

1. `String` jest UTF-8, więc jeden „widoczny znak” może zajmować wiele bajtów.
2. Indeks bajtowy nie musi wskazywać poprawnej granicy znaku.
3. Nie jest jednoznaczne, czy użytkownik chce bajt, `char`, grapheme cluster czy slice.
4. O(1) indexing po „znakach” nie jest gwarantowane dla UTF-8.

### Wewnętrzna reprezentacja

`String` jest wrapperem nad `Vec<u8>`. To oznacza, że `len()` zwraca liczbę **bajtów**, a nie liczbę „liter” w intuicyjnym sensie.

## Bajty, `char` i grapheme clusters

Rust rozróżnia co najmniej trzy poziomy patrzenia na tekst:

- bajty,
- Unicode scalar values (`char`),
- grapheme clusters (najbliższe ludzkiej intuicji „liter”).

Standard library daje bezpośrednie wsparcie dla bajtów i `char`, ale nie dla grapheme clusters.

## Slice’y stringów

Jeśli chcesz wycinać fragmenty tekstu, używasz slice’ów po **zakresach bajtów**:

```rust
let hello = "Здравствуйте";
let s = &hello[0..4];
```

To działa tylko wtedy, gdy granice są poprawnymi granicami UTF-8. Jeśli przetniesz w środku znaku wielobajtowego, program spanikuje w runtime.

## Iteracja po stringach

Po znakach Unicode (`char`):

```rust
for c in "Зд".chars() {
    println!("{c}");
}
```

Po bajtach:

```rust
for b in "Зд".bytes() {
    println!("{b}");
}
```

Wniosek praktyczny: przy pracy ze stringami trzeba być bardzo świadomym, czy operujesz na bajtach, scalar values czy czymś jeszcze wyższego poziomu.

## `HashMap<K, V>`

Hash map mapuje klucze typu `K` na wartości typu `V`.

### Tworzenie i insert

```rust
use std::collections::HashMap;

let mut scores = HashMap::new();

scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Yellow"), 50);
```

W przeciwieństwie do `vec![]`, standard library nie daje wbudowanego makra do konstrukcji `HashMap`.

### Odczyt wartości

```rust
let team_name = String::from("Blue");
let score = scores.get(&team_name).copied().unwrap_or(0);
```

`get` zwraca `Option<&V>`, więc zwykle trzeba:

- obsłużyć `None`,
- albo skopiować / sklonować wartość,
- albo pracować na referencji.

### Iteracja

```rust
for (key, value) in &scores {
    println!("{key}: {value}");
}
```

Kolejność iteracji jest arbitralna.

## Ownership w `HashMap`

Dla typów `Copy` wartości są kopiowane. Dla typów owned, np. `String`, klucze i wartości są przenoszone do mapy:

```rust
let field_name = String::from("Favorite color");
let field_value = String::from("Blue");

let mut map = HashMap::new();
map.insert(field_name, field_value);
```

Po `insert` wcześniejsze zmienne nie są już dostępne, jeśli zostały przeniesione.

## Aktualizacja `HashMap`

### Nadpisanie wartości

Ponowne `insert` dla tego samego klucza zastępuje poprzednią wartość:

```rust
scores.insert(String::from("Blue"), 10);
scores.insert(String::from("Blue"), 25);
```

Efekt: dla `Blue` zostaje `25`.

### Wstaw tylko jeśli brak

Najważniejszy idiom:

```rust
scores.entry(String::from("Yellow")).or_insert(50);
scores.entry(String::from("Blue")).or_insert(50);
```

Znaczenie:

- jeśli klucz istnieje, zachowaj starą wartość,
- jeśli nie istnieje, wstaw nową.

`or_insert` zwraca `&mut V`.

### Aktualizacja na podstawie starej wartości

Klasyczny przykład: liczenie słów.

```rust
use std::collections::HashMap;

let text = "hello world wonderful world";
let mut map = HashMap::new();

for word in text.split_whitespace() {
    let count = map.entry(word).or_insert(0);
    *count += 1;
}
```

To idiomatyczny wzorzec zliczania częstotliwości.

## Hashing function

Domyślnie `HashMap` używa `SipHash`, co daje odporność na pewne ataki DoS kosztem części wydajności. Jeśli profilowanie pokaże, że to za wolne, można podmienić hasher.

## Co zapamiętać

1. `Vec<T>` przechowuje elementy jednego typu obok siebie i dobrze nadaje się do sekwencji o zmiennym rozmiarze.
2. `v[index]` panikuje poza zakresem, a `v.get(index)` zwraca `Option`.
3. Referencje do elementów vectora i modyfikacja samego vectora w tym samym czasie mogą być zabronione z powodu możliwej realokacji.
4. `String` to owned UTF-8 text, a `&str` to string slice.
5. `String` nie wspiera indeksowania pojedynczym numerem, bo UTF-8 nie daje prostego modelu „znak pod indeksem”.
6. Do konkatenacji prostych stringów można użyć `+`, ale dla kilku elementów zwykle lepsze jest `format!`.
7. `HashMap<K, V>` przechowuje jednorodne typy kluczy i wartości oraz zwraca dane zwykle przez `Option` i referencje.
8. `entry(...).or_insert(...)` to podstawowy idiom dla warunkowego wstawiania i aktualizacji wartości.
