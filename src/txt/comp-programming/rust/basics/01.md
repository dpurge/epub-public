# 01

## Cel rozdziału

Rozdział 1 pokazuje minimalny próg wejścia w Rusta: instalację toolchainu, ręczną kompilację prostego programu oraz podstawy pracy z Cargo, które w praktyce staje się standardowym interfejsem do budowania projektów.

## Instalacja i narzędzia

Rust instaluje się standardowo przez `rustup`, który zarządza wersjami kompilatora i powiązanych narzędzi. Po instalacji warto od razu sprawdzić:

```console
$ rustc --version
$ cargo --version
```

W praktyce poza samym Rustem potrzebny bywa także linker; jeśli system zgłasza błędy linkowania, zwykle trzeba doinstalować kompilator C/C++.

Najważniejsze komendy administracyjne:

| Cel | Komenda |
|---|---|
| aktualizacja toolchainu | `rustup update` |
| odinstalowanie | `rustup self uninstall` |
| lokalna dokumentacja | `rustup doc` |

## Pierwszy program

Minimalny program wykonywalny w Ruście musi mieć funkcję `main`:

```rust
fn main() {
    println!("Hello, world!");
}
```

### Co tu warto zapamiętać

- `fn main()` definiuje punkt wejścia programu wykonywalnego.
- Ciało funkcji jest ujęte w klamry `{}`.
- `println!` to makro, a nie zwykła funkcja — stąd `!`.
- Większość instrukcji kończy się średnikiem `;`.
- Pliki źródłowe Rusta mają rozszerzenie `.rs`.

## Kompilacja a uruchomienie

Przy pracy bez Cargo najpierw kompilujesz kod, a dopiero potem uruchamiasz wynikowy plik wykonywalny:

```console
$ rustc main.rs
$ ./main
```

Na Windows uruchomienie zwykle wygląda jako `./main.exe` lub `.\\main`.

To ważna cecha modelu Rusta: jest to język kompilowany ahead-of-time. Efektem pracy kompilatora jest samodzielny plik wykonywalny, który można uruchamiać niezależnie od źródła.

## Cargo: standardowy sposób pracy

Cargo jest jednocześnie:

- systemem budowania,
- menedżerem pakietów,
- standardową strukturą projektu.

Nowy projekt tworzy się poleceniem:

```console
$ cargo new hello_cargo
$ cd hello_cargo
```

Cargo generuje typowy układ:

- `Cargo.toml` — metadane i zależności projektu,
- `src/main.rs` — kod programu,
- opcjonalnie repozytorium Git, jeśli nie jesteś już w istniejącym repo.

Przykładowy `Cargo.toml`:

```toml
[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2024"

[dependencies]
```

### Konwencje Cargo

- kod źródłowy trafia do `src/`,
- katalog główny projektu zawiera konfigurację, README, licencje itp.,
- zależności zapisuje się w sekcji `[dependencies]`,
- dokładne wersje zależności są blokowane w `Cargo.lock`.

## Najważniejsze komendy Cargo

| Komenda | Zastosowanie |
|---|---|
| `cargo new <nazwa>` | utworzenie nowego projektu |
| `cargo build` | kompilacja w trybie developerskim |
| `cargo run` | kompilacja i uruchomienie w jednym kroku |
| `cargo check` | szybkie sprawdzenie poprawności bez tworzenia pliku wykonywalnego |
| `cargo build --release` | build zoptymalizowany do wydania |

### Różnice praktyczne

- `cargo build` zapisuje wynik w `target/debug/`.
- `cargo run` oszczędza ręczne uruchamianie binarki.
- `cargo check` jest szybsze od `cargo build`, więc dobrze nadaje się do częstego sprawdzania kodu podczas pisania.
- `cargo build --release` tworzy wolniej, ale generuje szybszy program w `target/release/`.

## Co zapamiętać

1. Rust instaluje się zwykle przez `rustup`.
2. Najprostszy program wykonywalny zawiera `fn main()` i może używać `println!`.
3. `rustc` wystarcza do prostych przykładów, ale szybko staje się zbyt niskopoziomowy do codziennej pracy.
4. Cargo jest domyślnym sposobem tworzenia, budowania, uruchamiania i rozwijania projektów w Ruście.
5. W praktyce podstawowy workflow to: `cargo new` → `cargo check` / `cargo run` → `cargo build --release`.
