# 19

## Cel rozdziału

Rozdział 19 zbiera w jednym miejscu cały model pattern matching w Ruście. Patterny to nie tylko `match`, ale ogólny język opisu kształtu danych używany w wielu konstrukcjach języka.

## Czym jest pattern

Pattern opisuje kształt danych, który chcemy dopasować. Może zawierać:

- literały,
- zmienne,
- wildcardy,
- zakresy,
- destrukturyzację tuple / struct / enum / slice,
- warunki dodatkowe.

Przykłady patternów:

- `x`
- `(a, 3)`
- `Some(Color::Red)`

## Gdzie patterny występują

### `match`

Klasyczne miejsce użycia:

```rust
match x {
    None => None,
    Some(i) => Some(i + 1),
}
```

Pattern jest po lewej stronie `=>`.

Najważniejsza własność: `match` musi być wyczerpujący, chyba że użyjesz catch-all, np. `_`.

### `let`

To też jest pattern matching:

```rust
let x = 5;
```

Bardziej widoczne przy destrukturyzacji:

```rust
let (x, y, z) = (1, 2, 3);
```

### `if let`

Skrócona forma dla jednego interesującego patternu:

```rust
if let Some(color) = favorite_color {
    println!("Using your favorite color, {color}, as the background");
}
```

### `while let`

Powtarzaj dopóki pattern się zgadza:

```rust
while let Ok(value) = rx.recv() {
    println!("{value}");
}
```

### `for`

W `for` to, co stoi po `for`, też jest patternem:

```rust
for (index, value) in v.iter().enumerate() {
    println!("{index}: {value}");
}
```

### Parametry funkcji

Parametry funkcji również są patternami:

```rust
fn foo(x: i32) {
    // ...
}
```

A nawet:

```rust
fn print_coordinates(&(x, y): &(i32, i32)) {
    println!("Current location: ({x}, {y})");
}
```

## Refutable vs irrefutable

To kluczowe rozróżnienie.

### Irrefutable pattern

Zawsze pasuje.

Przykład:

```rust
let x = 5;
```

`x` dopasuje dowolną wartość.

### Refutable pattern

Może nie pasować.

Przykład:

```rust
if let Some(x) = maybe_value {
    // ...
}
```

`Some(x)` nie pasuje do `None`.

## Gdzie co wolno

| Konstrukcja | Wymaga |
|---|---|
| `let`, parametry funkcji, `for` | patternów irrefutable |
| `if let`, `while let`, `let...else` | mogą używać patternów refutable |
| `match` | patternów refutable, z pełnym pokryciem przypadków |

To ważne praktycznie: jeśli próbujesz użyć `Some(x)` w zwykłym `let`, kompilator zaprotestuje, bo nie ma co zrobić, gdy dopasowanie się nie powiedzie.

## Literały

Pattern może dopasowywać konkretną wartość:

```rust
match x {
    1 => println!("one"),
    2 => println!("two"),
    _ => println!("something else"),
}
```

## Zmienne i shadowing

Nazwana zmienna w patternie wiąże dopasowaną wartość i tworzy nowy scope.

To może prowadzić do shadowingu:

```rust
let x = Some(5);
let y = 10;

match x {
    Some(50) => println!("Got 50"),
    Some(y) => println!("Matched, y = {y}"),
    _ => println!("Default case, x = {x:?}"),
}

println!("at the end: x = {x:?}, y = {y}");
```

W `Some(y)` powstaje nowe `y`, które zasłania zewnętrzne `y`.

## Wiele patternów: `|`

Można dopasować kilka alternatyw w jednym ramieniu:

```rust
match x {
    1 | 2 => println!("one or two"),
    3 => println!("three"),
    _ => println!("anything"),
}
```

## Zakresy: `..=`

Działa dla liczb i `char`:

```rust
match x {
    1..=5 => println!("one through five"),
    _ => println!("something else"),
}
```

oraz np.:

```rust
match ch {
    'a'..='j' => println!("early ASCII letter"),
    'k'..='z' => println!("late ASCII letter"),
    _ => println!("something else"),
}
```

## Destrukturyzacja tuple

```rust
let (x, y, z) = (1, 2, 3);
```

Można też używać jej w `match`, `for`, parametrach funkcji itd.

## Destrukturyzacja struktur

Podstawowa forma:

```rust
struct Point {
    x: i32,
    y: i32,
}

let p = Point { x: 0, y: 7 };
let Point { x: a, y: b } = p;
```

Skrót, gdy nazwy mają być takie same jak pola:

```rust
let Point { x, y } = p;
```

Łączenie z literałami:

```rust
match p {
    Point { x, y: 0 } => println!("On the x axis at {x}"),
    Point { x: 0, y } => println!("On the y axis at {y}"),
    Point { x, y } => println!("On neither axis: ({x}, {y})"),
}
```

## Destrukturyzacja enumów

Pattern dla enumu odpowiada kształtowi danych wariantu:

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}

match msg {
    Message::Quit => println!("The Quit variant has no data to destructure."),
    Message::Move { x, y } => println!("Move in the x direction {x} and in the y direction {y}"),
    Message::Write(text) => println!("Text message: {text}"),
    Message::ChangeColor(r, g, b) => println!("Change color to red {r}, green {g}, and blue {b}"),
}
```

## Zagnieżdżone patterny

Patterny można dowolnie zagnieżdżać, np. enum w enumie, struct w tuple itd.

To jedna z najmocniejszych cech Rusta: bardzo precyzyjnie opisujesz oczekiwany kształt danych w jednym miejscu.

## Ignorowanie wartości

### `_`

Najbardziej podstawowy wildcard:

```rust
fn foo(_: i32, y: i32) {
    println!("This code only uses the y parameter: {y}");
}
```

`_` niczego nie wiąże i naprawdę ignoruje wartość.

### `_` wewnątrz większego patternu

```rust
match (setting_value, new_setting_value) {
    (Some(_), Some(_)) => {
        println!("Can't overwrite an existing customized value");
    }
    _ => {
        setting_value = new_setting_value;
    }
}
```

### Nazwa zaczynająca się od `_`

```rust
let _x = 5;
```

To tłumi warning o nieużywanej zmiennej, ale **dalej wiąże wartość**.

To różni się od gołego `_`.

### `_` vs `_x`

To ważna różnica semantyczna:

- `_` nie wiąże wartości,
- `_x` wiąże wartość i może przez to np. przejąć ownership.

## `..`

`..` ignoruje „resztę” struktury danych.

Przykład dla struct:

```rust
match origin {
    Point { x, .. } => println!("x is {x}"),
}
```

Przykład dla tuple:

```rust
match numbers {
    (first, .., last) => {
        println!("Some numbers: {first}, {last}");
    }
}
```

To przydatne przy większych danych, gdy interesują Cię tylko wybrane pola / pozycje.

Ważne: `..` musi być użyte jednoznacznie. Jeśli pattern robi się nieczytelny dla kompilatora, dostaniesz błąd o niejednoznaczności.

## Match guards

Match guard to dodatkowy warunek `if` po patternie:

```rust
match num {
    Some(x) if x % 2 == 0 => println!("The number {x} is even"),
    Some(x) => println!("The number {x} is odd"),
    None => (),
}
```

To przydaje się, gdy sam kształt danych nie wystarcza i potrzebujesz jeszcze warunku logicznego.

### Ważna uwaga

Przy match guards kompilator przestaje w pełni sprawdzać exhaustiveness tak silnie jak przy czystych patternach. To cena za dodatkową ekspresję.

### Match guard a shadowing

To także sposób na uniknięcie problemu z zasłanianiem zmiennych z zewnętrznego scope:

```rust
let x = Some(5);
let y = 10;

match x {
    Some(50) => println!("Got 50"),
    Some(n) if n == y => println!("Matched, n = {n}"),
    _ => println!("Default case, x = {x:?}"),
}
```

Tu `n` jest nową zmienną, a `y` pozostaje zewnętrznym `y`.

## Precedencja `|` z guardem

Guard dotyczy całego patternu po lewej:

```rust
match x {
    4 | 5 | 6 if y => println!("yes"),
    _ => println!("no"),
}
```

To znaczy:

```text
(4 | 5 | 6) if y
```

nie:

```text
4 | 5 | (6 if y)
```

## `@` bindings

Operator `@` pozwala jednocześnie:

- sprawdzić, czy wartość pasuje do patternu,
- i zachować ją w zmiennej.

Przykład:

```rust
match msg {
    Message::Hello { id: id_variable @ 3..=7 } => {
        println!("Found an id in range: {id_variable}");
    }
    Message::Hello { id: 10..=12 } => {
        println!("Found an id in another range");
    }
    Message::Hello { id } => {
        println!("Found some other id: {id}");
    }
}
```

Bez `@` musiałbyś wybrać: albo testowanie zakresu, albo wiązanie wartości. `@` pozwala mieć oba naraz.

## Co zapamiętać

1. Patterny są wszędzie: `match`, `let`, `if let`, `while let`, `for`, parametry funkcji.
2. `let`, `for` i parametry funkcji wymagają patternów irrefutable; `if let` i `while let` są po to, by używać patternów refutable.
3. Destrukturyzacja działa dla tuple, structów, enumów i kombinacji zagnieżdżonych.
4. `_` ignoruje wartość bez wiązania; `_x` nadal wiąże i może przejąć ownership.
5. `..` pozwala ignorować resztę struktury danych.
6. Match guards dodają zwykły warunek logiczny do patternu i są często najlepszym sposobem na precyzyjne dopasowanie bez dziwnego shadowingu.
7. `|` daje alternatywy patternów, a `..=` pozwala wygodnie dopasowywać zakresy.
8. `@` jest bardzo przydatne, gdy chcesz jednocześnie walidować kształt / zakres i zachować dopasowaną wartość do dalszego użycia.
