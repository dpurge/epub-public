# 20

## Cel rozdziału

Rozdział 20 zbiera zaawansowane mechanizmy języka, które nie są codziennym chlebem, ale warto wiedzieć, że istnieją:

- `unsafe`
- bardziej zaawansowane traity
- bardziej zaawansowane typy
- function pointers i zaawansowana praca z domknięciami
- makra deklaratywne i proceduralne

To rozdział typowo referencyjny: dużo mocy, ale używane punktowo.

## `unsafe`

Rust ma „drugą warstwę” języka: unsafe Rust. Działa jak zwykły Rust, ale pozwala wykonać operacje, których kompilator nie potrafi już zagwarantować jako memory-safe.

Unsafe nie wyłącza borrow checkera ani wszystkich innych zabezpieczeń. Daje tylko kilka dodatkowych uprawnień, a odpowiedzialność za poprawność przechodzi na programistę.

### Pięć „supermocy” unsafe

W `unsafe` można:

1. dereferencjonować raw pointer,
2. wołać unsafe functions / methods,
3. czytać i modyfikować `static mut`,
4. implementować unsafe trait,
5. odwoływać się do pól `union`.

## Raw pointers

Dwa podstawowe typy:

- `*const T`
- `*mut T`

Przykład:

```rust
let mut num = 5;

let r1 = &raw const num;
let r2 = &raw mut num;
```

Albo przez cast:

```rust
let address = 0x012345usize;
let r = address as *const i32;
```

### Czym różnią się od referencji

Raw pointers:

- mogą ignorować zwykłe reguły borrowingu,
- mogą być null,
- nie muszą wskazywać poprawnej pamięci,
- nie mają automatycznego cleanupu.

Samo utworzenie raw pointera jest dozwolone w safe Rust, ale jego dereferencja wymaga `unsafe`.

### Dereferencja raw pointera

```rust
let mut num = 5;
let r1 = &raw const num;
let r2 = &raw mut num;

unsafe {
    println!("r1 is: {}", *r1);
    println!("r2 is: {}", *r2);
}
```

To właśnie tu bierzesz odpowiedzialność za to, że wskaźnik jest prawidłowy.

## Unsafe functions

Funkcję można oznaczyć jako unsafe, jeśli wywołujący musi spełnić dodatkowy kontrakt:

```rust
unsafe fn dangerous() {}

unsafe {
    dangerous();
}
```

To sygnał: dokumentacja tej funkcji jest częścią kontraktu bezpieczeństwa.

## Bezpieczne API nad unsafe

Jedna z najważniejszych praktyk w Rust: użyj małego `unsafe` wewnątrz, ale opakuj go w bezpieczne API. Standard library robi to cały czas.

To najlepszy model pracy z unsafe: izolować je i minimalizować jego zasięg.

## `static mut` i FFI

Rozdział wspomina też dwa typowe zastosowania unsafe:

- dostęp do `static mut`,
- interfejs z kodem C / obcym ABI.

To obszary niskopoziomowe i potencjalnie niebezpieczne, ale konieczne dla system programming i interoperacyjności.

## Advanced traits

## Associated types

Associated type wiąże placeholder typu z traitem.

Klasyczny przykład:

```rust
pub trait Iterator {
    type Item;

    fn next(&mut self) -> Option<Self::Item>;
}
```

Zaleta względem generyków w traitcie:

- implementor wybiera konkretny typ tylko raz,
- nie ma wieloznaczności typu w każdym użyciu.

To jest lepsze tam, gdzie dany trait naturalnie ma jeden „powiązany” typ wyniku / elementu.

## Domyślne parametry generyczne

Przykład z `Add`:

```rust
trait Add<Rhs = Self> {
    type Output;

    fn add(self, rhs: Rhs) -> Self::Output;
}
```

Domyślnie prawa strona operatora (`Rhs`) jest tego samego typu co `Self`, ale można to nadpisać.

## Operator overloading

Rust nie pozwala definiować własnych operatorów, ale pozwala przeciążać istniejące przez traity ze `std::ops`.

Przykład:

```rust
use std::ops::Add;

#[derive(Debug, PartialEq)]
struct Point {
    x: i32,
    y: i32,
}

impl Add for Point {
    type Output = Point;

    fn add(self, other: Point) -> Point {
        Point {
            x: self.x + other.x,
            y: self.y + other.y,
        }
    }
}
```

## Fully qualified syntax

Potrzebne, gdy kilka traitów albo typ i trait mają identycznie nazwane metody / funkcje.

Schemat:

```rust
<Type as Trait>::function(receiver_if_method, ...)
```

Przykład praktyczny:

```rust
trait Pilot {
    fn fly(&self);
}

trait Wizard {
    fn fly(&self);
}

struct Human;

impl Pilot for Human {
    fn fly(&self) {
        println!("This is your captain speaking.");
    }
}

impl Wizard for Human {
    fn fly(&self) {
        println!("Up!");
    }
}

impl Human {
    fn fly(&self) {
        println!("*waving arms furiously*");
    }
}

let person = Human;
Pilot::fly(&person);
Wizard::fly(&person);
Human::fly(&person);
```

A dla funkcji skojarzonych bez `self` może być potrzebne pełne:

```rust
<Dog as Animal>::baby_name()
```

## Supertraits

Trait może wymagać implementacji innego traitu:

```rust
use std::fmt::Display;

trait OutlinePrint: Display {
    fn outline_print(&self) {
        let output = self.to_string();
        let len = output.len();
        println!("{}", "*".repeat(len + 4));
        println!("*{}*", " ".repeat(len + 2));
        println!("* {output} *");
        println!("*{}*", " ".repeat(len + 2));
        println!("{}", "*".repeat(len + 4));
    }
}
```

Tutaj `OutlinePrint` wymaga `Display`, bo opiera się na `to_string()`.

## Newtype pattern a traity zewnętrzne

Orphan rule blokuje implementację zewnętrznego traitu dla zewnętrznego typu. Obejściem jest newtype:

```rust
use std::fmt;

struct Wrapper(Vec<String>);

impl fmt::Display for Wrapper {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "[{}]", self.0.join(", "))
    }
}
```

To daje lokalny typ, na którym wolno implementować zewnętrzny trait.

## Advanced types

## Newtype

Newtype to cienki wrapper wokół istniejącego typu:

```rust
struct Meters(u32);
```

Zastosowania:

- większe bezpieczeństwo typów,
- oddzielenie jednostek / znaczeń,
- enkapsulacja implementacji,
- obejście orphan rule.

## Type aliases

Alias nie tworzy nowego typu, tylko nową nazwę:

```rust
type Kilometers = i32;
```

To tylko synonim. `Kilometers` i `i32` są tym samym typem dla kompilatora.

Bardzo przydatne do skracania długich sygnatur:

```rust
type Thunk = Box<dyn Fn() + Send + 'static>;
```

Albo do standaryzacji `Result`:

```rust
type Result<T> = std::result::Result<T, std::io::Error>;
```

## Never type: `!`

`!` oznacza typ, który nigdy nie produkuje wartości.

Przykład:

```rust
fn bar() -> ! {
    panic!();
}
```

Typowe użycia:

- `panic!`,
- `continue`,
- nieskończona pętla.

Przydaje się, bo `!` może zostać skojarzony z dowolnym innym typem w wyrażeniach, gdzie sterowanie już nie wraca.

## DST i `Sized`

Rust domyślnie zakłada, że typy mają rozmiar znany w compile time (`Sized`).

Problemem są dynamicznie sized types, np. `str` bezpośrednio. Dlatego pracuje się na wskaźnikach do nich, np. `&str`, które mają znany rozmiar samego wskaźnika + metadanych.

To też tłumaczy, czemu obiekty traitowe występują przez wskaźniki (`&dyn Trait`, `Box<dyn Trait>`), a nie jako nagie wartości.

## Function pointers i domknięcia

## `fn` jako typ funkcji

Można przekazywać zwykłe funkcje jako argumenty:

```rust
fn add_one(x: i32) -> i32 {
    x + 1
}

fn do_twice(f: fn(i32) -> i32, arg: i32) -> i32 {
    f(arg) + f(arg)
}
```

`fn` to function pointer, nie trait.

## Funkcje jako substytut domknięcia

Function pointers implementują `Fn`, `FnMut` i `FnOnce`, więc można ich używać tam, gdzie API oczekuje domknięcia.

Przykład z `map`:

```rust
let list_of_numbers = vec![1, 2, 3];
let list_of_strings: Vec<String> =
    list_of_numbers.iter().map(ToString::to_string).collect();
```

Można też używać konstruktorów wariantów enumów jako function pointers.

## Zwracanie domknięć

Nie zwracasz domknięcia „po typie konkretnym”, bo każde domknięcie ma swój unikalny anonimowy typ. Typowy sposób:

```rust
fn returns_closure() -> impl Fn(i32) -> i32 {
    |x| x + 1
}
```

Jeśli musisz zwracać różne domknięcia z kilku miejsc i ujednolicić ich typ, zwykle kończysz na obiekcie traitowym, np. `Box<dyn Fn(i32) -> i32>`.

## Makra

Makra to metaprogramowanie: kod, który generuje kod.

Główne rodziny:

- deklaratywne: `macro_rules!`
- proceduralne:
  - custom `derive`
  - attribute-like
  - function-like

## Makra vs funkcje

Makra mają moce, których funkcje nie mają:

- mogą przyjmować zmienną liczbę argumentów,
- działają na tokenach przed właściwą kompilacją,
- mogą generować implementacje i struktury kodu, których zwykła funkcja wykonywana w czasie działania nie może wytworzyć.

Koszt: są trudniejsze do pisania, czytania i debugowania niż zwykłe funkcje.

## `macro_rules!`

Podstawowy model deklaratywny:

```rust
macro_rules! my_vec {
    ( $( $x:expr ),* ) => {
        {
            let mut temp_vec = Vec::new();
            $(
                temp_vec.push($x);
            )*
            temp_vec
        }
    };
}
```

Wywołanie:

```rust
let v = my_vec![1, 2, 3];
```

To jest wzorzec „matchuj strukturę tokenów i wygeneruj kod zastępczy”.

## Procedural macros

Działają bardziej jak funkcje transformujące `TokenStream` w `TokenStream`.

Główne rodzaje:

- `#[derive(...)]`
- atrybuty własne
- makra funkcyjne

Custom derive to najbardziej praktyczny pierwszy przypadek: generowanie implementacji traitu dla typu na podstawie analizy deklaracji struktury / enumu.

## Co zapamiętać

1. `unsafe` daje dostęp do kilku operacji wyłączonych z safe Rust, ale nie wyłącza całej reszty systemu bezpieczeństwa.
2. Raw pointers są bardziej prymitywne niż referencje: mogą być null, nie muszą być poprawne i wymagają ostrożności.
3. Najlepsza praktyka z unsafe to zamykanie go w małych blokach i wystawianie bezpiecznego API.
4. Associated types wiążą typ z traitem raz na implementację i są często lepsze niż generyki w samym traitcie.
5. Default generic params i traity z `std::ops` stoją za przeciążaniem operatorów.
6. Fully qualified syntax rozwiązuje konflikty identycznych nazw metod / funkcji.
7. Newtype daje prawdziwy nowy typ i pomaga w bezpieczeństwie typów oraz obejściu orphan rule; type alias daje tylko nową nazwę.
8. `!` reprezentuje ścieżki wykonania, które nigdy nie zwracają wartości.
9. Domknięcia można zwracać przez `impl Fn...` albo obiekty traitowe, a zwykłe funkcje można przekazywać przez typ `fn`.
10. Makra generują kod w compile time i dają możliwości niedostępne zwykłym funkcjom.
