# 05

## Cel rozdziału

Rozdział 5 pokazuje, jak używać `struct` do modelowania powiązanych danych oraz jak dopisywać do typów własne zachowania przez `impl` i metody. To podstawowy mechanizm budowania własnych typów domenowych w Ruście.

## Po co `struct`

Tuple grupuje dane, ale nie nadaje nazw poszczególnym polom. `struct` robi to jawnie, dzięki czemu kod lepiej komunikuje znaczenie danych.

```rust
struct User {
    active: bool,
    username: String,
    email: String,
    sign_in_count: u64,
}
```

Najważniejsza przewaga nad tuple:

- pola mają nazwy,
- nie trzeba pamiętać pozycji typu `0` / `1`,
- łatwiej utrzymać poprawność i czytelność.

## Tworzenie instancji i dostęp do pól

Instancję tworzy się przez `key: value`:

```rust
let user1 = User {
    active: true,
    username: String::from("someusername123"),
    email: String::from("someone@example.com"),
    sign_in_count: 1,
};
```

Dostęp do pól używa notacji kropkowej:

```rust
let email = user1.email;
```

Jeśli chcesz zmieniać pola, mutowalna musi być cała instancja:

```rust
let mut user1 = User {
    active: true,
    username: String::from("someusername123"),
    email: String::from("someone@example.com"),
    sign_in_count: 1,
};

user1.email = String::from("another@example.com");
```

Rust nie pozwala oznaczyć pojedynczego pola jako mutowalnego niezależnie od reszty instancji.

## Field init shorthand

Gdy nazwa zmiennej i nazwa pola są takie same, można użyć skrótu:

```rust
fn build_user(email: String, username: String) -> User {
    User {
        active: true,
        username,
        email,
        sign_in_count: 1,
    }
}
```

To skraca kod bez zmiany semantyki.

## Struct update syntax

Nową instancję można zbudować częściowo z innej instancji:

```rust
let user2 = User {
    email: String::from("another@example.com"),
    ..user1
};
```

Najważniejsze skutki:

- pola jawnie podane dostają nowe wartości,
- reszta pól jest kopiowana lub przenoszona z podanej instancji,
- `..user1` musi być na końcu,
- jeśli któreś pole jest typu move-only, część danych z `user1` może zostać przeniesiona i `user1` może przestać być w pełni używalny.

## Tuple structs

Tuple struct nadaje nazwę typowi, ale nie polom:

```rust
struct Color(i32, i32, i32);
struct Point(i32, i32, i32);
```

Przydaje się, gdy:

- chcesz nowy, odrębny typ,
- nazwy poszczególnych pól byłyby zbędne lub oczywiste,
- nie chcesz używać „gołego” tuple.

Mimo identycznych składowych `Color` i `Point` to różne typy.

## Unit-like structs

Można też zdefiniować strukturę bez pól:

```rust
struct AlwaysEqual;
```

Ma sens wtedy, gdy potrzebujesz typu dla zachowania, ale bez danych. Rozdział wskazuje to głównie jako przygotowanie do późniejszej pracy z traitami.

## Ownership w strukturach

Rozdział świadomie używa `String`, a nie `&str`, wewnątrz `User`, żeby każda instancja posiadała własne dane. Struktury mogą przechowywać referencje, ale wymaga to lifetime’ów, które pojawią się później.

## Przykład: refaktoryzacja do `Rectangle`

Rozdział pokazuje dobrą motywację dla `struct`: najpierw osobne zmienne, potem tuple, a na końcu czytelniejszy model danych.

Zamiast:

```rust
fn area(width: u32, height: u32) -> u32 {
    width * height
}
```

lepiej:

```rust
struct Rectangle {
    width: u32,
    height: u32,
}

fn area(rectangle: &Rectangle) -> u32 {
    rectangle.width * rectangle.height
}
```

Korzyść:

- sygnatura mówi, że chodzi o jeden prostokąt,
- `width` i `height` są semantycznie związane,
- trudniej pomylić znaczenie argumentów.

## `Debug` i `dbg!`

Zwykłe `{}` w `println!` nie działa automatycznie dla struktur. Do debugowego wypisywania trzeba wyprowadzić trait `Debug`:

```rust
#[derive(Debug)]
struct Rectangle {
    width: u32,
    height: u32,
}
```

Wtedy można używać:

```rust
println!("rect1 is {rect1:?}");
println!("rect1 is {rect1:#?}");
```

- `{:?}` — format debug,
- `{:#?}` — czytelniejsza, „pretty” wersja.

Przydatne jest też `dbg!`:

```rust
dbg!(&rect1);
```

Ważne własności `dbg!`:

- wypisuje też plik i numer linii,
- pisze na `stderr`,
- zwraca przekazaną wartość,
- przy przekazaniu przez wartość przejmuje ownership, więc często podaje się referencję.

## Metody i `impl`

Metoda to funkcja zdefiniowana w kontekście typu, zwykle z pierwszym parametrem `self`.

```rust
struct Rectangle {
    width: u32,
    height: u32,
}

impl Rectangle {
    fn area(&self) -> u32 {
        self.width * self.height
    }
}
```

Wywołanie:

```rust
let rect1 = Rectangle {
    width: 30,
    height: 50,
};

println!("The area of the rectangle is {} square pixels.", rect1.area());
```

## Formy `self`

Pierwszy parametr metody może mieć kilka typowych postaci:

| Postać | Znaczenie |
|---|---|
| `self` | przejęcie ownership |
| `&self` | niemutowalne pożyczenie |
| `&mut self` | mutowalne pożyczenie |

W praktyce:

- `&self` służy do odczytu,
- `&mut self` do modyfikacji,
- `self` rzadziej, gdy metoda ma zużyć lub przekształcić obiekt.

`&self` to skrót od `self: &Self`, gdzie `Self` oznacza typ z bieżącego `impl`.

## Metody a funkcje

Główne zalety metod:

- lepsza organizacja kodu wokół typu,
- krótsze sygnatury,
- naturalna składnia `obiekt.metoda()`.

Rust automatycznie dobiera referencjonowanie / dereferencjonowanie odbiorcy metody, więc nie ma osobnego operatora w stylu C++ `->`.

## Metoda o tej samej nazwie co pole

Metoda może nazywać się tak samo jak pole. Nawiasy rozstrzygają, czy chodzi o metodę, czy pole:

- `rect.width` — pole,
- `rect.width()` — metoda.

Rozdział wspomina też ideę getterów: Rust nie generuje ich automatycznie.

## Metody z dodatkowymi parametrami

Przykład z rozdziału:

```rust
impl Rectangle {
    fn can_hold(&self, other: &Rectangle) -> bool {
        self.width > other.width && self.height > other.height
    }
}
```

To typowy wzorzec:

- `self` jest odbiorcą operacji,
- inne argumenty zachowują się jak zwykłe parametry funkcji,
- wynik może być np. `bool`.

## Associated functions

Nie każda funkcja w `impl` musi być metodą. Jeśli nie ma parametru `self`, jest **associated function**:

```rust
impl Rectangle {
    fn square(size: u32) -> Self {
        Self {
            width: size,
            height: size,
        }
    }
}
```

Wywołanie:

```rust
let sq = Rectangle::square(3);
```

To odpowiednik funkcji „fabrykującej” lub konstruktora. `new` jest konwencją, ale nie słowem kluczowym języka.

## Wiele bloków `impl`

Jeden typ może mieć wiele osobnych bloków `impl`. To legalne i czasem praktyczne, choć w prostych przykładach zwykle nie ma potrzeby rozdzielania metod.

## Co zapamiętać

1. `struct` jest preferowany nad tuple tam, gdzie ważne są nazwy i znaczenie pól.
2. Mutowalność dotyczy całej instancji, nie pojedynczych pól.
3. Field init shorthand skraca inicjalizację, gdy nazwy zmiennych i pól są takie same.
4. Struct update syntax (`..inna_instancja`) reuse’uje pola, ale może też przenosić ownership.
5. `#[derive(Debug)]` daje szybki debug print dla własnych typów.
6. Metody definiuje się w `impl`, zwykle z `&self` albo `&mut self`.
7. Associated functions nie mają `self` i wywołuje się je przez `Typ::funkcja(...)`.
8. Dobra struktura danych zwykle upraszcza sygnatury funkcji i ogranicza klasy błędów semantycznych.
