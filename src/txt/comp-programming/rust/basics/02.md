# 02

## Cel rozdziału

Rozdział 2 buduje prostą grę w zgadywanie liczby i przy okazji wprowadza kilka podstawowych elementów Rusta w praktyce: `let`, `match`, `loop`, typ `Result`, parsowanie danych wejściowych oraz użycie zewnętrznej biblioteki przez Cargo.

## Szkielet programu

Gra działa według prostego schematu:

1. program losuje liczbę od 1 do 100,
2. użytkownik wpisuje strzał,
3. program porównuje strzał z liczbą docelową,
4. pętla trwa aż do trafienia.

## Zależność zewnętrzna: `rand`

Losowanie nie jest częścią standardowej biblioteki, więc projekt dodaje zależność w `Cargo.toml`:

```toml
[dependencies]
rand = "0.10.1"
```

Najważniejsze konsekwencje:

- Cargo pobiera crate z rejestru,
- zależności są wersjonowane semantycznie,
- dokładne wersje użyte przy buildzie trafiają do `Cargo.lock`,
- `Cargo.lock` stabilizuje powtarzalność buildów.

## Minimalny przebieg gry

Kluczowe elementy końcowej wersji programu:

```rust
use rand::prelude::*;
use std::cmp::Ordering;
use std::io;

fn main() {
    println!("Guess the number!");

    let secret_number = rand::rng().random_range(1..=100);

    loop {
        println!("Please input your guess.");

        let mut guess = String::new();

        io::stdin()
            .read_line(&mut guess)
            .expect("Failed to read line");

        let guess: u32 = match guess.trim().parse() {
            Ok(num) => num,
            Err(_) => continue,
        };

        println!("You guessed: {guess}");

        match guess.cmp(&secret_number) {
            Ordering::Less => println!("Too small!"),
            Ordering::Greater => println!("Too big!"),
            Ordering::Equal => {
                println!("You win!");
                break;
            }
        }
    }
}
```

## Najważniejsze elementy języka

| Element | Rola |
|---|---|
| `let` | wiązanie nazwy z wartością |
| `let mut` | zmienna mutowalna |
| `String::new()` | tworzy pusty napis do zebrania wejścia |
| `io::stdin().read_line(...)` | czyta linię ze standardowego wejścia |
| `trim().parse()` | usuwa białe znaki i konwertuje tekst na liczbę |
| `match` | rozgałęzienie po wariantach enumów |
| `loop` | pętla nieskończona |
| `break` | wyjście z pętli |
| `continue` | przejście do następnej iteracji |

## Wejście użytkownika

Wejście jest czytane do napisu:

```rust
let mut guess = String::new();

io::stdin()
    .read_line(&mut guess)
    .expect("Failed to read line");
```

Co warto zapamiętać:

- `read_line` dopisuje dane do istniejącego `String`, dlatego potrzebne jest `&mut guess`,
- `&mut` oznacza przekazanie mutowalnej referencji,
- `read_line` zwraca `Result`, więc operacja może się nie udać.

## `Result` i `expect`

Na wcześniejszym etapie rozdział pokazuje prosty model obsługi błędów przez `expect`:

```rust
io::stdin()
    .read_line(&mut guess)
    .expect("Failed to read line");
```

Znaczenie:

- `Ok(...)` oznacza sukces,
- `Err(...)` oznacza błąd,
- `expect(...)` kończy program z komunikatem, jeśli wynik to `Err`.

To wygodne na etapie prostych przykładów, ale nie zawsze jest najlepszą strategią w docelowym programie.

## Losowanie liczby

Sekretna liczba jest generowana tak:

```rust
let secret_number = rand::rng().random_range(1..=100);
```

Najważniejsze szczegóły:

- `rand::rng()` daje generator liczb losowych,
- `random_range(1..=100)` losuje z zakresu domkniętego,
- zapis `1..=100` obejmuje zarówno `1`, jak i `100`.

## Parsowanie tekstu na liczbę

Dane z terminala trafiają najpierw jako tekst. Aby porównać je liczbowo, trzeba je sparsować:

```rust
let guess: u32 = match guess.trim().parse() {
    Ok(num) => num,
    Err(_) => continue,
};
```

Tu pojawia się kilka ważnych rzeczy naraz:

- `trim()` usuwa końcowy newline po naciśnięciu Enter,
- `parse()` próbuje przekonwertować napis na inny typ,
- `u32` wymusza dodatnią liczbę całkowitą 32-bitową,
- `match` rozróżnia przypadek poprawny i błędny,
- `continue` pomija niepoprawny input i wraca na początek pętli.

Rozdział pokazuje też zjawisko **shadowingu**: ponowne użycie nazwy `guess` dla wartości o innym typie.

## Porównanie i `Ordering`

Porównanie działa przez `cmp` i enum `Ordering`:

```rust
match guess.cmp(&secret_number) {
    Ordering::Less => println!("Too small!"),
    Ordering::Greater => println!("Too big!"),
    Ordering::Equal => {
        println!("You win!");
        break;
    }
}
```

Wnioski:

- `cmp` zwraca jeden z wariantów: `Less`, `Greater`, `Equal`,
- `match` wymusza jawne obsłużenie przypadków,
- trafienie kończy grę przez `break`.

## Najważniejsza logika sterowania

Rozdział wykorzystuje dwa centralne mechanizmy:

- `loop` do wielokrotnego pytania o liczbę,
- `match` do obsługi zarówno błędów, jak i wyniku porównania.

To pierwszy przykład, w którym Rust pokazuje preferencję do jawnego modelowania możliwych stanów zamiast ukrywania ich w wyjątkach lub wartościach specjalnych.

## Co zapamiętać

1. Typowy projekt w Ruście bardzo szybko korzysta z Cargo i zewnętrznych crate’ów.
2. Wejście z terminala trafia jako `String`, więc zwykle wymaga `trim()` i `parse()`.
3. `Result` jest podstawowym nośnikiem informacji o sukcesie lub błędzie operacji.
4. `match` służy zarówno do obsługi błędów, jak i do rozgałęziania po enumach takich jak `Ordering`.
5. `loop` + `break` + `continue` tworzą prosty, czytelny model sterowania dla interaktywnych programów.
6. `Cargo.lock` zapewnia powtarzalne buildy przez przypięcie konkretnych wersji zależności.
