# 06

## Cel rozdziału

Rozdział 6 wprowadza `enum` i pattern matching. `enum` pozwala modelować typ, którego wartość może być jedną z kilku ściśle określonych postaci, a `match`, `if let` i `let...else` pozwalają te postacie rozróżniać i bezpiecznie rozpakowywać.

## Po co `enum`

`struct` grupuje pola, a `enum` mówi: „wartość jest jedną z kilku możliwych wariantów”. To dobre do modelowania stanów rozłącznych.

Przykład podstawowy:

```rust
enum IpAddrKind {
    V4,
    V6,
}
```

Wartość takiego typu może być tylko jednym wariantem naraz:

```rust
let four = IpAddrKind::V4;
let six = IpAddrKind::V6;
```

## Enum jako pełny typ domenowy

Enum może nie tylko rozróżniać warianty, ale też przechowywać dane bezpośrednio w wariancie:

```rust
enum IpAddr {
    V4(String),
    V6(String),
}
```

To bywa lepsze niż `struct { kind, address }`, bo wariant i dane są złączone w jednej konstrukcji.

Jeszcze ważniejsze: różne warianty mogą mieć **różne typy i ilości danych**:

```rust
enum IpAddr {
    V4(u8, u8, u8, u8),
    V6(String),
}
```

## Warianty jako konstruktory

Wariant enumu zachowuje się jak funkcja konstruująca wartość danego typu. Np. `IpAddr::V4(...)` tworzy instancję `IpAddr`.

## Enumy z różnymi kształtami danych

Rozdział pokazuje też bardziej zróżnicowany przykład:

```rust
enum Message {
    Quit,
    Move { x: i32, y: i32 },
    Write(String),
    ChangeColor(i32, i32, i32),
}
```

W jednym enumie można więc mieć warianty:

- bez danych,
- z polami nazwanymi jak w `struct`,
- z jednym argumentem,
- z kilkoma argumentami tuple-style.

To jest ważna przewaga enumów nad zbiorem osobnych struktur: wszystko nadal pozostaje jednym typem.

## Metody na enumach

Tak jak dla `struct`, także dla `enum` można pisać `impl` i metody:

```rust
impl Message {
    fn call(&self) {
        // body omitted
    }
}
```

## `Option<T>`

Najważniejszy enum ze standard library:

```rust
enum Option<T> {
    None,
    Some(T),
}
```

Znaczenie:

- `Some(T)` — wartość istnieje,
- `None` — wartości brak.

To zastępuje ideę `null`, ale w sposób jawny i typowany. Dzięki temu kompilator zmusza do obsługi braku wartości.

### Najważniejsze własności `Option`

- jest w prelude,
- `Some` i `None` są dostępne bez importu,
- `Option<T>` i `T` to różne typy.

To ostatnie jest kluczowe: nie można traktować `Option<i32>` jak zwykłego `i32` bez jawnej obsługi przypadku `None`.

## `match`

`match` to główny mechanizm rozgałęzienia po wariantach enumów i innych wzorcach.

Przykład klasyczny:

```rust
enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter,
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter => 25,
    }
}
```

## Jak działa `match`

Każde ramię ma postać:

- **pattern**
- `=>`
- **expression**

Wykonywane jest pierwsze pasujące ramię. Wynik całego `match` to wynik wyrażenia z dopasowanego ramienia.

Jeśli kod w ramieniu jest dłuższy, używa się bloku `{ ... }`.

## Wiązanie wartości z wariantu

`match` może nie tylko rozpoznać wariant, ale też wyciągnąć dane z jego wnętrza.

Przykład z dodatkową wartością w `Quarter`:

```rust
enum UsState {
    Alabama,
    Alaska,
    // ...
}

enum Coin {
    Penny,
    Nickel,
    Dime,
    Quarter(UsState),
}

fn value_in_cents(coin: Coin) -> u8 {
    match coin {
        Coin::Penny => 1,
        Coin::Nickel => 5,
        Coin::Dime => 10,
        Coin::Quarter(state) => {
            println!("State quarter from {state:?}!");
            25
        }
    }
}
```

`state` staje się nazwą dla danych przechowywanych w wariancie.

## `match` z `Option<T>`

Typowy wzorzec:

```rust
fn plus_one(x: Option<i32>) -> Option<i32> {
    match x {
        None => None,
        Some(i) => Some(i + 1),
    }
}
```

To jest podstawowa technika pracy z `Option`: jawnie obsłużyć brak wartości oraz przypadek obecności wartości.

## Exhaustiveness

Najważniejsza własność `match`: musi być **wyczerpujący**. Kompilator wymaga obsługi wszystkich możliwych przypadków.

To jeden z głównych powodów, dla których `Option` jest bezpieczniejszy niż `null`: nie da się „zapomnieć”, że wartości może nie być, bez błędu kompilacji.

## Catch-all i `_`

Jeśli nie interesują Cię wszystkie szczegóły, można użyć ramienia domyślnego.

Wersja z wiązaniem wartości:

```rust
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    other => move_player(other),
}
```

Wersja z ignorowaniem wartości:

```rust
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => reroll(),
}
```

Jeśli naprawdę nic nie ma się wydarzyć:

```rust
match dice_roll {
    3 => add_fancy_hat(),
    7 => remove_fancy_hat(),
    _ => (),
}
```

`_` dopasowuje wszystko, ale niczego nie wiąże.

## `if let`

Gdy interesuje Cię tylko jeden wariant, pełny `match` bywa zbyt rozwlekły. Wtedy używa się `if let`.

Zamiast:

```rust
match config_max {
    Some(max) => println!("The maximum is configured to be {max}"),
    _ => (),
}
```

krócej:

```rust
if let Some(max) = config_max {
    println!("The maximum is configured to be {max}");
}
```

To składniowy skrót dla `match`, gdy:

- chcesz obsłużyć jeden wzorzec,
- resztę ignorujesz.

### `if let` z `else`

Można dodać alternatywną gałąź:

```rust
if let Coin::Quarter(state) = coin {
    println!("State quarter from {state:?}!");
} else {
    count += 1;
}
```

Trade-off jest prosty:

- mniej boilerplate’u,
- mniej gwarancji exhaustiveness niż przy `match`.

## `let...else`

Rozdział wprowadza też `let...else` jako wygodny sposób pozostania na „happy path”.

Idea:

- jeśli wzorzec pasuje, związane wartości trafiają do zewnętrznego scope,
- jeśli nie pasuje, `else` musi zakończyć bieżący przepływ, np. przez `return`.

To wygodne, gdy chcesz szybko rozpakować przypadek oczekiwany i wcześnie wyjść w przeciwnym razie.

## Porównanie narzędzi

| Konstrukcja | Kiedy używać |
|---|---|
| `match` | gdy trzeba obsłużyć wiele wariantów i zależy Ci na exhaustiveness |
| `if let` | gdy interesuje Cię jeden wariant, a resztę ignorujesz |
| `let...else` | gdy chcesz wydzielić oczekiwany wzorzec i wcześnie wyjść przy niepowodzeniu |

## Co zapamiętać

1. `enum` modeluje rozłączne warianty jednego typu.
2. Warianty enumów mogą przechowywać dane i każdy wariant może mieć inny „kształt”.
3. `Option<T>` zastępuje `null` przez jawne `Some(T)` / `None`.
4. `Option<T>` nie jest tym samym co `T`; brak wartości trzeba obsłużyć jawnie.
5. `match` jest podstawowym narzędziem rozpakowywania enumów i musi być wyczerpujący.
6. Wzorce w `match` mogą wiązać dane z wnętrza wariantu.
7. `_` służy jako catch-all, gdy nie chcesz używać dopasowanej wartości.
8. `if let` i `let...else` są krótszymi formami dla częstych przypadków, ale `match` pozostaje najbardziej pełnym i rygorystycznym narzędziem.
